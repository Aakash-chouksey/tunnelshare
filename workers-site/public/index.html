How it works

Upload → share → self-destruct

Three steps, same as the real app.

1

Upload

Pick a file (max 50 MB), expiry (1 / 24 / 72 h) and max downloads. Server stores bytes locally and returns a link plus a 6-digit code — shown once.

2

Share on two channels

Send the /s/<id> link one way and the code another. The receiver enters the code to unlock the download.

3

It self-destructs

Status resolves to ACTIVE, EXHAUSTED, EXPIRED or LOCKED. Expired bytes are deleted; 5 wrong codes lock the share.

Features

Small, sharp, self-hostable

Everything the Flask app does today — no database server, no object store.

Code-gated downloads

6-digit code, salted SHA-256 hash, constant-time compare. The code is shown once at upload.

5-strike lockout

5 wrong guesses flip the share to LOCKED. Brute force gets nowhere.

Expiry + download caps

1 / 24 / 72-hour expiry and 1–100 max downloads. State machine: ACTIVE, EXHAUSTED, EXPIRED, LOCKED.

50 MB, zero config

SQLite + local upload dir. pip install -r requirements.txt and run.

Cloudflare Tunnel ready

Serve localhost securely with cloudflared tunnel --url. No port forwarding.

Owner delete

POST /api/delete with id + code removes bytes and row immediately.

FAQ

Questions, answered

Where are files stored? Is there R2 / D1?

No. The app is static-landing + self-hosted Flask: SQLite rows and files on local disk. This landing page itself is static only — no R2, no D1.

What happens when a share expires?

Status flips to EXPIRED and the file bytes are deleted so content is unrecoverable, while the row is kept so the API can still report EXPIRED instead of 404.

What if someone guesses the code?

Each wrong guess increments an attempt counter. After 5 wrong codes the share is LOCKED. Send link and code on different channels.

How do I deploy this landing page?

Run cd workers-site && wrangler deploy (lead deploys after review). See workers-site/README.md for the custom-domain steps.
